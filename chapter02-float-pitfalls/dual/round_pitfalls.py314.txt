== 坑 A：round(2.675, 2) 得 2.67 —— 错在字面量，不在 round ==
A hex(2.675) -> 0x1.5666666666666p+1
A Decimal(2.675) 精确存储值 -> 2.67499999999999982236431605997495353221893310546875
A round(2.675, 2) -> 2.67
A format(2.675, '.2f') -> 2.67
A 存储值 2.674999… 严格小于 2.675：无平局，怎么舍都是 2.67
A Decimal('2.675').quantize(0.01) 默认 half-even -> 2.68
A Decimal('2.675').quantize(0.01) HALF_UP 四舍五入 -> 2.68
A 对照 1.005：round(1.005, 2) -> 1.0
A 对照 1.005 的存储值 -> 1.00499999999999989341858963598497211933135986328125
== 坑 B：round(0.5) == 0 —— 这才是银行家舍入（round-half-even）==
B round(0.5) -> 0
B round(1.5) -> 2
B round(2.5) -> 2
B round(3.5) -> 4
B round(4.5) -> 4
B round(-0.5) -> 0
B round(-1.5) -> -2
B round(-2.5) -> -2
B 规律 -> 偶数邻居胜出：0.5→0、1.5→2、2.5→2、3.5→4、4.5→4
B x.5 都能被二进制精确表示：真平局，才轮到 half-even 出场
B HALF_UP 期望 round(0.5) 是 1，实测 0；round(2.5) 期望 3，实测 2
B Decimal 默认也是 half-even：Decimal('2.5') 取整 -> 2
B Decimal('3.5') 取整 -> 4
== 两个坑一句话分开 ==
SUMMARY 坑A -> 字面量准头问题：2.675 存进来就变成 2.674999…，与舍入规则无关
SUMMARY 坑B -> 规则问题：round 用 round-half-even（银行家），平局不总是进位
